# Router — EARS Specs

Design: `router-design.md`. Implementation: `reference/scripts/next_step.py`.

## Invocation

- [x] **ROUTE-CLI-001**: On every call that ROUTE-KILL-001 does not stop, `next_step.py` shall run the workstream-state wake for the resolved workstream before applying any event.
- [x] **ROUTE-CLI-002**: If the wake status is not `OK`, then `next_step.py` shall return action `stop` with that status and change no state.
- [x] **ROUTE-CLI-003**: `next_step.py` shall accept at most one event, of type `start`, `result`, `user`, or `mode`, from the `--event` file or from stdin when the argument is `-`.
- [x] **ROUTE-CLI-004**: When called with `--dry-run`, `next_step.py` shall return the decision it would make without writing `state.json`.
- [x] **ROUTE-CLI-005**: `next_step.py` shall print exactly one JSON decision to stdout, exit `0` for every decision, and exit non-zero only for a usage error.
- [x] **ROUTE-CLI-006**: `next_step.py` shall include `action`, `phase` (the phase after the decision), and a one-line `summary` in every decision.
- [x] **ROUTE-CLI-007**: `next_step.py` shall be the only writer of every `state.json` field except `identity`, `config` (except `config.mode` after the workstream is created), `anchors.workstream_base_sha`, `anchors.stale_shas`, and `dropped`.
- [x] **ROUTE-CLI-008**: On every call, `next_step.py` shall check the kill switch, then run the wake, then apply the event if any, then handle drift, then check for a dirty tree, then dispatch, returning at the first step that yields a stop or a pause.
- [x] **ROUTE-KILL-001**: When `.STOP_FORGE` exists at the root of the main worktree or of the worktree `next_step.py` runs in, `next_step.py` shall return `stop` with status `KILL_SWITCH`, `phase` `null`, and a `detail` listing the absolute path of each such file once, without running the wake, reading the event, or reading or writing any workstream file.

## Modes

- [x] **ROUTE-MODE-001**: When a `mode` event names one of `delivery`, `collab-plan`, `collab-qa`, `collab-dev`, `collab-code`, or `collab` while `lifecycle.current_phase` is not `DONE`, `next_step.py` shall set `config.mode` to it and return action `mode_set` with `mode`, without handling drift, checking the tree, or dispatching.
- [x] **ROUTE-MODE-002**: If a `mode` event names any other value, or arrives while `lifecycle.current_phase` is `DONE`, then `next_step.py` shall return `stop` with `EVENT_INVALID` and change no state.
- [x] **ROUTE-MODE-003**: When applying a `mode` event while `lifecycle.awaiting` is a `plan_approval` raised by `STAGE_COMPLETE` and the new mode is neither `collab-plan` nor `collab`, `next_step.py` shall answer that pause with `approve`.
- [x] **ROUTE-MODE-004**: When applying a `mode` event while `lifecycle.awaiting` is a `plan_approval` raised by `READY_FOR_QA` and the new mode is `delivery`, `next_step.py` shall answer that pause with `approve`.
- [x] **ROUTE-MODE-005**: When applying a `mode` event while `lifecycle.awaiting` is an `edit_window` raised after `QA_SKEL` or `DEV_STUB` and the new mode is neither `collab-code` nor `collab`, raised after `POST_QA` and the new mode is not `collab-qa`, `collab-code`, or `collab`, or raised after `DEV_FULL` and the new mode is not `collab-dev`, `next_step.py` shall answer that pause with `continue`.
- [x] **ROUTE-MODE-006**: When `next_step.py` answers a pause per ROUTE-MODE-003, ROUTE-MODE-004, ROUTE-MODE-005, or ROUTE-MODE-009, it shall make the same state changes the user's answer would make and dispatch nothing on that call, and its next call without an event shall dispatch what that answer leads to, with the same notes and agent mode.
- [x] **ROUTE-MODE-009**: When applying a `mode` event of `delivery` while `lifecycle.awaiting` is a `council_signoff` for a blocker other than `CONCERNS` whose stored ruling has `requires_user` `false`, `next_step.py` shall apply the ruling as ROUTE-BLK-006 applies it in `delivery`, recording `approved_by: "auto"`.
- [x] **ROUTE-MODE-010**: If `config.mode` holds a value other than `delivery`, `collab-plan`, `collab-qa`, `collab-dev`, `collab-code`, or `collab`, then `next_step.py` shall return `stop` with `STATE_INVALID` naming the value and change no state.
- [x] **ROUTE-MODE-007**: While `config` has no `mode`, `next_step.py` shall route the workstream as mode `collab`.
- [x] **ROUTE-MODE-008**: When re-dispatching a planning phase while applying a `revise` answer, `next_step.py` shall give the dispatch the agent mode of the dispatch it replaces.

## Re-derivation

- [x] **ROUTE-REDO-001**: When called with no event while `lifecycle.awaiting` is set, `next_step.py` shall return the same pause again.
- [x] **ROUTE-REDO-002**: When called with no event while `lifecycle.dispatched` is set, no drift is reported, and ROUTE-DRIFT-008 does not apply, `next_step.py` shall return the invocation envelope stored in `lifecycle.invoke` again, unchanged except for `agent_prefix` and `dispatch_as`, which it shall set per ROUTE-DISP-010.
- [x] **ROUTE-REDO-003**: When called with no event while `lifecycle.current_phase` is `INIT`, `next_step.py` shall return `stop` with `NOT_STARTED` and change no state.
- [x] **ROUTE-REDO-004**: When called with no event while `lifecycle.current_phase` is `DONE` and `lifecycle.promote` is `null` or absent, `next_step.py` shall return `done`.
- [x] **ROUTE-REDO-005**: When called with no event while `lifecycle.current_phase` is `DONE`, `lifecycle.promote` is not `null`, and no drift is reported, `next_step.py` shall return `close` with `promote` equal to `lifecycle.promote` and change no state.

## Dispatch

- [x] **ROUTE-DISP-001**: When `next_step.py` dispatches an agent, it shall record exactly `{dispatch_id, agent, mode, base_sha}` in `lifecycle.dispatched`, plus `proposal_mtime_ns` per ROUTE-IDEA-024 or ROUTE-IDEA-025 for a `PROPOSE` dispatch, with a new unique `dispatch_id` and `base_sha` equal to `HEAD`.
- [x] **ROUTE-DISP-002**: When `next_step.py` dispatches an agent, the invocation envelope shall carry `dispatch_id`, `agent`, `mode`, `state_path`, `base_sha`, `assigned_scope`, `context_refs`, and `notes`, plus `stage` for `forge-qa`, `forge-dev`, and `forge-planner` in every mode but `propose`.
- [x] **ROUTE-DISP-003**: `next_step.py` shall set the envelope's `stage` to `LID-S<n>` for LID planning stage `n`, `NAIVE-PLAN` for naive planning, `COLLAB-SKEL` for QA skeletons, `COLLAB-STUB` for dev stubs, `LID-S5` or `NAIVE-TESTS` for QA full tests in a LID or naive repository, `LID-S6` or `NAIVE-IMPL` for dev full implementation in a LID or naive repository, and `REPAIR` for repair dispatches.
- [x] **ROUTE-DISP-004**: When dispatching `forge-qa` or `forge-dev` in `QA_SKEL`, `DEV_STUB`, `QA_FULL`, or `DEV_FULL`, `next_step.py` shall set `assigned_scope` to `scope_manifest.remaining`.
- [x] **ROUTE-DISP-005**: When `next_step.py` dispatches an agent, it shall store the complete invocation envelope in `lifecycle.invoke`.
- [x] **ROUTE-DISP-006**: When `next_step.py` dispatches an agent while `anchors.last_known_head_sha` is `null`, it shall set `anchors.last_known_head_sha` to `HEAD`.
- [x] **ROUTE-DISP-007**: When dispatching `forge-verifier`, `next_step.py` shall set `assigned_scope` to `scope_manifest.assigned`.
- [x] **ROUTE-DISP-008**: When re-dispatching the same phase while applying a `revise` answer, a `reject` answer, or an `approve` answer to a spoke's `human_code_approval`, `next_step.py` shall set `context_refs` to the replaced dispatch's `lifecycle.invoke.context_refs` followed by any new entries not already in it, except for `forge-reporter`, whose `context_refs` follow ROUTE-BUILD-033, ROUTE-IDEA-005, and ROUTE-IDEA-006.
- [x] **ROUTE-DISP-009**: While the workstream's state directory holds `task.md`, when `next_step.py` dispatches `forge-planner`, `forge-reviewer` in `REVIEW_INTERNAL`, or `forge-scout` in `RECON` of an `idea`- or `triage`-flow workstream, it shall put the absolute path of `task.md` first in the invocation envelope's `context_refs` and list it nowhere else in them.
- [x] **ROUTE-DISP-010**: When `next_step.py` dispatches an agent, the invocation envelope shall also carry `agent_prefix`, read from `forge_install.json` in the directory containing `next_step.py` (`""` when that file does not exist), and `dispatch_as`, equal to `agent_prefix` followed by `agent`.
- [x] **ROUTE-DISP-011**: If `forge_install.json` in the directory containing `next_step.py` exists but is not a JSON object whose `agent_prefix` is a string, then `next_step.py` shall return `stop` with `INSTALL_INVALID`, naming the file, and change no state.
- [ ] **ROUTE-DISP-012**: When `next_step.py` dispatches `forge-dev` in any phase, `REPAIR` included, while `lifecycle.plan_input` is set, it shall list `lifecycle.plan_input` in the invocation envelope's `context_refs` exactly once, after every other entry when the dispatch's other `context_refs` do not hold it.

## Result envelopes

- [x] **ROUTE-ENV-001**: If a `result` event's `dispatch_id` or `agent` differs from `lifecycle.dispatched`, then `next_step.py` shall return `stop` with `ENVELOPE_INVALID` and change no state.
- [x] **ROUTE-ENV-015**: If a `result` event passes ROUTE-ENV-001 and `envelopes/<dispatch_id>.guard.json` beside `state.json` is missing, is not a JSON object whose `agents` is a list, or does not list `lifecycle.dispatched.agent`, then `next_step.py` shall return `stop` with `GUARD_INACTIVE` and change no state, before any other check on the envelope.
- [x] **ROUTE-ENV-016**: When `next_step.py` stops with `GUARD_INACTIVE`, the `detail` shall name the guard record's absolute path and the known causes: a project-scope install in a `-p` session or in a folder whose workspace trust was not accepted, a managed policy allowing only managed hooks, and no `python3` on `PATH`.
- [x] **ROUTE-ENV-017**: When `next_step.py` stops with `GUARD_INACTIVE` in an `idea`- or `triage`-flow workstream, the `detail` shall also state whether `HEAD` differs from `lifecycle.dispatched.base_sha` and list every path `git status --porcelain` reports in the worktree.
- [x] **ROUTE-ENV-002**: If a `result` event's `status` is neither `ERROR` nor accepted in the current phase by ROUTE-ENV-014, or is excluded for the dispatch's agent or mode by ROUTE-ENV-012, then `next_step.py` shall return `stop` with `ENVELOPE_INVALID` and change no state.
- [x] **ROUTE-ENV-014**: `next_step.py` shall accept, besides `ERROR`, only these statuses per phase: `RECON` and `PR_FETCH` `OK`; `PROPOSE` `PROPOSAL_READY`, `CONCERNS`; `PLAN_S1`–`PLAN_S4` `STAGE_COMPLETE`, `READY_FOR_QA`, `CONCERNS`; `PLAN` `READY_FOR_QA`, `CONCERNS`; `POST_PLAN` and `POST_QA` `PASS`, `AUDIT_FAILED`; `PRE_QA` and `PRE_DEV` `PARTIAL_REMAINING`, `NOTHING_REMAINING`; `QA_SKEL` `SKELETON_COMMITTED`, `CONTRACT_MISMATCH`, `HUMAN_CODE_CHANGE_REQUESTED`; `QA_FULL` `TESTS_COMMITTED`, `CONTRACT_MISMATCH`, `HUMAN_CODE_CHANGE_REQUESTED`; `DEV_STUB` `STUBS_COMMITTED`, `TEST_CHANGE_REQUESTED`, `CONTRACT_MISMATCH`, `HUMAN_CODE_CHANGE_REQUESTED`; `DEV_FULL` `IMPLEMENTATION_COMPLETE`, `TEST_CHANGE_REQUESTED`, `CONTRACT_MISMATCH`, `HUMAN_CODE_CHANGE_REQUESTED`; `VERIFY_FINAL` `PASS`, `AUDIT_FAILED`, `TESTS_FAILED`; `REVIEW_INTERNAL` `REVIEW_APPROVED`, `CHANGES_REQUESTED`; `PUBLISH` `PUBLISHED`, `MERGE_READY`, `MERGE_BLOCKED`, `PUBLISH_REFUSED`; `CI_WATCH` `CI_GREEN`, `CI_FAILED`, `CI_NONE`; `REPORT` `REPORT_DRAFTED`, `REPORT_SENT`; `RECONCILE` `PASS`; `COUNCIL` `COUNCIL_RULING`; `REPAIR` `REPAIR_COMMITTED`, `CONTRACT_MISMATCH`, `HUMAN_CODE_CHANGE_REQUESTED`; `PR_REVIEW` `PR_REVIEW_READY`.
- [x] **ROUTE-ENV-012**: `next_step.py` shall not accept `READY_FOR_QA` from a `strict` dispatch in `PLAN_S1` through `PLAN_S3`; `STAGE_COMPLETE` from a dispatch in `PLAN_S4` or any `auto` dispatch; `REPORT_SENT` from a `draft` dispatch; `REPORT_DRAFTED` from a `send` dispatch; `HUMAN_CODE_CHANGE_REQUESTED` from `forge-planner`; or `CONTRACT_MISMATCH` in `REPAIR` from an agent other than `forge-qa`.
- [x] **ROUTE-ENV-013**: When `next_step.py` accepts a `result` event with status `PUBLISHED`, `PR_REVIEW_READY`, `PROPOSAL_READY`, or `REPORT_DRAFTED`, it shall set `lifecycle.report_input` to the absolute path of `envelopes/<dispatch_id>.json` beside `state.json`.
- [x] **ROUTE-ENV-003**: If a `result` event's `head_sha` is neither the current `HEAD` nor an ancestor of it, then `next_step.py` shall return `stop` with `ENVELOPE_INVALID` and change no state.
- [x] **ROUTE-ENV-004**: If a `result` event from `forge-verifier`, `forge-reviewer`, `forge-scout`, `forge-council`, `forge-reporter`, `forge-publisher`, or `forge-planner` dispatched with mode `propose` has a `head_sha` different from the dispatch's `base_sha`, then `next_step.py` shall return `stop` with `ENVELOPE_INVALID` and change no state.
- [x] **ROUTE-ENV-005**: If a council `result` event's `ruling.route_to`, or the `route_to` of any entry of `ruling.options`, names an agent other than `forge-planner`, `forge-qa`, or `forge-dev`, then `next_step.py` shall return `stop` with `ENVELOPE_INVALID` and change no state.
- [x] **ROUTE-ENV-006**: When `next_step.py` accepts a `result` event, it shall clear `lifecycle.dispatched` and set `lifecycle.last_agent` and `lifecycle.last_status` from the envelope.
- [x] **ROUTE-ENV-007**: When `next_step.py` accepts a `result` event from `forge-planner`, `forge-qa`, or `forge-dev`, it shall set `anchors.last_known_head_sha` to the envelope's `head_sha`.
- [x] **ROUTE-ENV-008**: When an accepted `result` event from a committing agent spans commits that do not all carry `Forge-Agent` equal to that agent, `next_step.py` shall apply the envelope and then handle the other commits as drift.
- [x] **ROUTE-ENV-010**: When an accepted `result` event's `head_sha` is a proper ancestor of `HEAD`, `next_step.py` shall apply the envelope and then handle the commits after `head_sha` as drift.
- [x] **ROUTE-ENV-011**: When an accepted `result` event leads to a pause and its range holds commits handled as drift per ROUTE-ENV-008 or ROUTE-ENV-010, `next_step.py` shall leave `anchors.last_known_head_sha` at its value before the call.
- [x] **ROUTE-ENV-009**: When any agent returns status `ERROR`, `next_step.py` shall return `stop` with `AGENT_ERROR` and the envelope's `escalation.details`, changing only `lifecycle.dispatched`, `lifecycle.last_agent`, and `lifecycle.last_status`.

## Build flow

- [x] **ROUTE-BUILD-001**: When a `build`-flow workstream at `INIT` receives a `start` event, `next_step.py` shall go to `RECON` if `identity.issue` is set, otherwise to `PLAN_S1` in a LID repository or `PLAN` in a naive repository.
- [x] **ROUTE-BUILD-002**: When `forge-scout` returns `OK` in `RECON` of a `build`-flow workstream, `next_step.py` shall go to the first planning phase and add the workstream's `scout/` directory to the planner's `context_refs`.
- [x] **ROUTE-BUILD-003**: Except per ROUTE-MODE-008, `next_step.py` shall dispatch `forge-planner` in `PLAN_S<n>` with mode `strict` while `config.mode` is `collab-plan` or `collab` and with mode `auto` otherwise, and in `PLAN` with mode `naive`.
- [x] **ROUTE-BUILD-004**: When `forge-planner` returns `STAGE_COMPLETE` in `PLAN_S<n>`, `next_step.py` shall pause `plan_approval` while `config.mode` is `collab-plan` or `collab`, and on `approve` go to `PLAN_S<n+1>`; while `config.mode` is any other mode it shall go to `PLAN_S<n+1>` without pausing.
- [x] **ROUTE-BUILD-005**: When `forge-planner` returns `READY_FOR_QA` while `config.mode` is not `delivery`, `next_step.py` shall store the envelope's `scope.assigned`, which may be empty, in `scope_manifest.assigned` and pause `plan_approval`; on `approve` it shall set `anchors.plan_base_sha` to `HEAD`, `scope_manifest.remaining` to `scope_manifest.assigned`, and `scope_manifest.completed` to an empty list, and go to `POST_PLAN`.
- [x] **ROUTE-BUILD-006**: When the user answers `plan_approval` with `revise`, `next_step.py` shall re-dispatch the current planning phase with the user's `notes`.
- [x] **ROUTE-BUILD-041**: When `forge-planner` returns `READY_FOR_QA` while `config.mode` is `delivery`, `next_step.py` shall store the envelope's `scope.assigned` in `scope_manifest.assigned`, set `anchors.plan_base_sha` to `HEAD`, `scope_manifest.remaining` to `scope_manifest.assigned`, and `scope_manifest.completed` to an empty list, and go to `POST_PLAN` without pausing.
- [ ] **ROUTE-BUILD-047**: When `next_step.py` accepts a `result` event with status `READY_FOR_QA`, it shall set `lifecycle.plan_input` to the absolute path of `envelopes/<dispatch_id>.json` beside `state.json`.
- [x] **ROUTE-BUILD-007**: When `forge-verifier` returns `PASS` in `POST_PLAN` while `scope_manifest.assigned` is not empty, `next_step.py` shall set `lifecycle.two_pass`, when it is `null`, to `true` if `config.mode` is `collab-code` or `collab` and to `false` otherwise, and then go to `PRE_QA` with `lifecycle.pass` set to `1` if `lifecycle.two_pass` is `true`, otherwise to `QA_FULL`.
- [x] **ROUTE-BUILD-035**: When `forge-verifier` returns `PASS` in `POST_PLAN` while `scope_manifest.assigned` is empty, `next_step.py` shall go to `VERIFY_FINAL`.
- [x] **ROUTE-BUILD-008**: When `forge-verifier` returns `PARTIAL_REMAINING` or `NOTHING_REMAINING` in `PRE_QA` or `PRE_DEV`, `next_step.py` shall replace `scope_manifest.completed` and `scope_manifest.remaining` with the envelope's `scope`.
- [x] **ROUTE-BUILD-009**: When `forge-verifier` returns `PARTIAL_REMAINING` in `PRE_QA`, `next_step.py` shall go to `QA_SKEL` in pass 1 and `QA_FULL` in pass 2.
- [x] **ROUTE-BUILD-010**: When `forge-verifier` returns `NOTHING_REMAINING` in `PRE_QA`, `next_step.py` shall go to `PRE_DEV`.
- [x] **ROUTE-BUILD-011**: When `forge-qa` returns `SKELETON_COMMITTED` in `QA_SKEL`, `next_step.py` shall pause `edit_window` while `config.mode` is `collab-code` or `collab`, and on `continue` go to `PRE_DEV`; while `config.mode` is any other mode it shall go to `PRE_DEV` without pausing.
- [x] **ROUTE-BUILD-012**: When `forge-verifier` returns `PARTIAL_REMAINING` in `PRE_DEV`, `next_step.py` shall go to `DEV_STUB` in pass 1 and `DEV_FULL` in pass 2.
- [x] **ROUTE-BUILD-013**: When `forge-verifier` returns `NOTHING_REMAINING` in `PRE_DEV`, `next_step.py` shall set `lifecycle.pass` to `2` and go to `PRE_QA` in pass 1, and go to `VERIFY_FINAL` in pass 2.
- [x] **ROUTE-BUILD-014**: When `forge-dev` returns `STUBS_COMMITTED` in `DEV_STUB`, `next_step.py` shall pause `edit_window` while `config.mode` is `collab-code` or `collab`, and on `continue` set `lifecycle.pass` to `2` and go to `PRE_QA`; while `config.mode` is any other mode it shall set `lifecycle.pass` to `2` and go to `PRE_QA` without pausing.
- [x] **ROUTE-BUILD-015**: When `forge-qa` returns `TESTS_COMMITTED` in `QA_FULL`, `next_step.py` shall go to `POST_QA`.
- [x] **ROUTE-BUILD-016**: When `forge-verifier` returns `PASS` in `POST_QA` while `config.mode` is `collab-qa`, `collab-code`, or `collab`, `next_step.py` shall pause `edit_window`; on `continue` it shall go to `PRE_DEV` if `lifecycle.two_pass` is `true` and to `DEV_FULL` otherwise.
- [x] **ROUTE-BUILD-032**: When `forge-verifier` returns `PASS` in `POST_QA` while `config.mode` is `delivery`, `collab-plan`, or `collab-dev`, `next_step.py` shall go without pausing to `PRE_DEV` if `lifecycle.two_pass` is `true` and to `DEV_FULL` otherwise.
- [x] **ROUTE-BUILD-017**: When `forge-dev` returns `IMPLEMENTATION_COMPLETE` in `DEV_FULL`, `next_step.py` shall pause `edit_window` while `config.mode` is `collab-dev`, and on `continue` go to `VERIFY_FINAL`; while `config.mode` is any other mode it shall go to `VERIFY_FINAL` without pausing.
- [x] **ROUTE-BUILD-018**: When `forge-verifier` returns `PASS` in `VERIFY_FINAL`, `next_step.py` shall run the gate's commit checks with the workstream's state over `anchors.workstream_base_sha..HEAD`, or over every first-parent commit reachable from `HEAD` when `anchors.workstream_base_sha` is `null`.
- [x] **ROUTE-BUILD-019**: When the `VERIFY_FINAL` commit checks pass, `next_step.py` shall set `anchors.verifier_pass_sha` to `HEAD` and go to `REVIEW_INTERNAL`.
- [x] **ROUTE-BUILD-020**: If the `VERIFY_FINAL` commit checks report error findings that are all `HUMAN_CODE_MODIFIED`, then `next_step.py` shall pause `human_code_approval` presenting each finding's commit, path, and lines, and leave `anchors.verifier_pass_sha` unchanged.
- [x] **ROUTE-BUILD-036**: When the user answers a `human_code_approval` raised by the commit checks with `approve`, `next_step.py` shall append to `approvals` one `{id, agent, paths, ranges, base_sha, approved_by: "user"}` per finding, with `agent` the commit's `Forge-Agent`, `paths` a list holding the finding's path, `ranges` an object mapping that path to the finding's lines, and `base_sha` the commit's parent, and dispatch `VERIFY_FINAL` again.
- [x] **ROUTE-BUILD-037**: When the user answers a `human_code_approval` raised by the commit checks with `reject`, `next_step.py` shall return `stop` with `GATE_REJECTED`.
- [x] **ROUTE-BUILD-038**: If the `VERIFY_FINAL` commit checks report any error finding other than `HUMAN_CODE_MODIFIED`, then `next_step.py` shall return `stop` with `GATE_UNREPAIRABLE` and the error findings, and leave `anchors.verifier_pass_sha` unchanged.
- [x] **ROUTE-BUILD-021**: When `forge-reviewer` returns `REVIEW_APPROVED` in `REVIEW_INTERNAL`, `next_step.py` shall set `anchors.reviewer_pass_sha` to `HEAD` and pause `publish_approval` with options `approve` (which requires an `option` of `push` or `merge`) and `hold`.
- [x] **ROUTE-BUILD-039**: When `next_step.py` pauses `publish_approval` in a workstream whose `config.repo_mode` is `LID`, it shall call `lid_check.py`'s importable `check` with the workstream's state and, when the result's `merged_specs` is not empty, record those IDs in the `publish_approval` pause payload's `merged_specs` and add a line naming each ID to the pause's question.
- [x] **ROUTE-BUILD-042**: When `next_step.py` pauses `publish_approval` in a workstream whose `config.repo_mode` is `LID` and the `lid_check.py` result's `unmarked_specs` is not empty, it shall record those IDs in the `publish_approval` pause payload's `unmarked_specs` and add a line naming each ID to the pause's question.
- [x] **ROUTE-BUILD-040**: When `next_step.py` pauses `publish_approval` in a workstream whose `config.repo_mode` is not `LID`, it shall set neither `merged_specs` nor `unmarked_specs` in the payload, and in a LID workstream it shall set neither key whose `lid_check.py` list is empty and add no line for it.
- [x] **ROUTE-BUILD-022**: When the user answers `publish_approval` with `approve` and option `push` or `merge`, `next_step.py` shall go to `PUBLISH` and dispatch `forge-publisher` with that mode; on `hold` it shall pause `publish_approval` again.
- [x] **ROUTE-BUILD-043**: When `next_step.py` pauses `publish_approval`, it shall run `git remote get-url origin` in the workstream worktree and, when it exits nonzero, set `no_origin` to `true` in the pause payload and add a line to the question saying push is unavailable; when it exits zero, it shall leave `no_origin` out of the payload.

- [x] **ROUTE-PAUSE-002**: If a `user` event's `awaiting` differs from `lifecycle.awaiting.kind`, or its `decision` is not one of that pause's options, then `next_step.py` shall return `stop` with `EVENT_INVALID` and change no state.
